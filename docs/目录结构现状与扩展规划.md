# FirmForge 目录结构与扩展规划

> **版本**: v2.0  
> **日期**: 2026-07-22  
> **状态**: 最终架构（manifest 驱动）  

---

## 一、设计原则

### 1.1 两区分离

| 区域 | 路径 | 内容特征 | 分发方式 |
|------|------|----------|----------|
| **A区（仓库）** | `c:\MyLab\MCU\` | 纯文本：Python 代码、manifest 清单、板定义、官方例程、文档 | git 追踪，pip 随包发布 |
| **B区（用户）** | `~/.firmforge/` | 大文件：SDK 源码包、编译器、烧录器、编译缓存 | `ff setup` 按需下载 |

**核心逻辑**：A 区体积小、可离线浏览；B 区按 manifest 下载大文件。A 区的 `vendor/manifests/` 是所有外部资源的**唯一真相源（Single Source of Truth）**。

### 1.2 manifest 驱动

```
vendor/manifests/          ← A区（真相源：定义版本、URL、SHA256）
         ↓
   ff setup 按需下载
         ↓
~/.firmforge/packages/     ← B区（物理实体：cores、libraries、variants）
~/.firmforge/toolchains/   ← B区（二进制：avr-gcc、avrdude、arm-gcc）
```

### 1.3 按平台分组

每新增一个 MCU 系列，在 `vendor/manifests/` 下新增对应 manifest，B 区按其下载：

```
vendor/manifests/
├── core/arduino_avr_core.yaml     → ~/.firmforge/packages/arduino/avr/
├── tools/avr_gcc.yaml             → ~/.firmforge/toolchains/avr-gcc/
├── vendors/stm32_cube_f1.yaml     → ~/.firmforge/packages/stm32/f1/  (预留)
└── ...
```

## 三、路径解析规则

### 3.1 Arduino Core（头文件/库）

搜索优先级（`build.py:_compile_with_arduino_core()`）：

```
① ~/.firmforge/packages/arduino/avr/1.8.6/   ← B区（ff setup 安装）
② vendor/arduino/                             ← A区 fallback（git clone 直接可用）
```

### 3.2 工具链（编译器/烧录器）

通过 `toolchain.py:resolve_toolchain()` 自动查找：

```
① ~/.firmforge/toolchains/<tool>/             ← 规范路径（优先）
② ~/AppData/Local/mcu-tools/<tool>/           ← 旧安装兼容
③ WinGet / 系统 PATH                          ← 系统级安装
```

## 四、资源归属判定矩阵

| 内容 | 示例 | 特征 | 归属 | 理由 |
|------|------|------|------|------|
| **API 头文件** | Arduino.h, CMSIS, HAL_Driver | 纯文本、平台特有 | B区 `packages/` | 版本独立、按需下载 |
| **库源码** | SPI, Wire, Ethernet | 纯文本、平台特有 | B区 `packages/` | 同上 |
| **引脚映射** | pins_arduino.h, variant.cpp | 板型配置 | B区 `packages/` | 同上 |
| **编译器** | avr-gcc, arm-none-eabi-gcc | 二进制、200~500MB | B区 `toolchains/` | 大体积、平台独立 |
| **烧录/调试器** | avrdude, openocd, stlink | 二进制、10~50MB | B区 `toolchains/` | 大体积、平台独立 |
| **官方例程** | Blink.ino, LEDToggle | 纯文本、小体积 | A区 `vendor/` | 基准测试数据 |
| **manifest 清单** | arduino_avr_core.yaml | 纯文本、真相源 | A区 `vendor/manifests/` | 版本锁定的唯一入口 |
| **板定义** | board.json | 纯文本、项目特定 | A区 `boards/` | git 追踪 |
| **L3 第三方库** | Adafruit_Sensor | 源代码、版本独立 | B区 `libraries/` | 用户按需下载 |

### 核心公式

```
vendor/manifests/   = 真相源（纯文本 · YAML · git 追踪）
B区 packages/       = SDK 物理实体（大体积 · 版本独立 · 按需下载）
B区 toolchains/     = 二进制工具（大体积 · 多平台共享 · 按需下载）
```

## 五、平台扩展流程

### 5.1 新增平台（以 STM32 为例）

```
1. 创建 vendor/manifests/vendors/stm32_cube_f1.yaml
   → 定义版本、下载 URL、SHA256、映射路径

2. 创建 boards/stm32f103c8t6/
   ├── board.json
   └── apps/

3. 新增 firmforge/providers/stm32/
   ├── build.py    ← arm-none-eabi-gcc 编译
   └── flash.py    ← openocd/stlink 烧录

4. 添加 arm-gcc 和 openocd 的 manifest:
   vendor/manifests/tools/arm_gcc.yaml
   vendor/manifests/tools/openocd.yaml

5. ff setup → 下载 STM32 SDK + ARM 工具链到 B区
```

### 5.2 manifest 引入时机

manifest 是**基础架构组件**，从 v2.0（本文档对应版本）开始启用。新平台接入时必须提供对应的 manifest 文件。
